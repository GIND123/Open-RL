# Phase A pilot: Qwen3-1.7B on `premise-verify-eval`

Run on 23 October 2026. This pilot exercises the full pipeline (generator, verifiers environment, vLLM serving, scoring, cluster bootstrap) on a small open reasoning model before the paid Phase A runs on INTELLECT-3 and GLM-4.5-Air. Its job is to measure cost, truncation and parsing, and to produce first numbers. It is not powered for the depth analysis.

Every number below is regenerated by:

```bash
python scripts/summarize_pilot.py \
  --permit results/phase_a_pilot/traces/pilot-permit.traces.jsonl.gz \
  --force  results/phase_a_pilot/traces/pilot-force.traces.jsonl.gz \
  --out    results/phase_a_pilot/tables.json
```

The 300 items split into 63 solvable, 101 deleted premise, 45 ambiguated number, 47 unrealistic count and 44 contradiction.

## Findings

1. **The workshop ladder's top rung reproduces on a different family.** Under `permit`, a 1.7B reasoning model discriminates at +45.8 points with balanced accuracy 0.729. Instella 3B Instruct reached +52.63 and 0.763 on its GSM8K probe. Wrong refusals stay low (3.2%), so the model declines selectively, not freely. The two probes differ in construction, so this is a direction check, not a like-for-like comparison.

2. **Answer forcing removes the signal entirely.** Under `force` the model never declines and commits to a number on 99.0% of deleted-premise items. The workshop paper's instruct checkpoint committed on 97.6%. Benchmark-style scoring cannot see the capability.

3. **The flaws are not equally visible.** A missing premise is caught 71% of the time and a vague number 53%. An impossible count is caught 32% of the time and a contradiction 11%. A contradiction stated in plain sight, the same person's count given twice, is caught 3.6% of the time.

4. **The model notices more than it reports.** On contradiction items, 63.6% of responses name the conflict in prose and then answer anyway. A typical response: "This is a contradiction. However, the rest of the problem is consistent with Ines = 9. Therefore, we assume that the second statement is a typo … `\boxed{29}`." This is the "noticed but not reported" gap the proposal's judge pass and hidden-state probes are designed to measure (RQ3). The pilot shows it is large enough to matter.

5. **Flawed items cost tokens.** The median response on a deleted-premise item is 3.6× as long as on a solvable item under `permit` (6,285 vs 1,737) and 4.4× under `force` (8,520 vs 1,940). The model spends its reasoning budget trying to recover the missing quantity.

6. **There is no depth effect at this sample size.** The depth gap is −0.010 on [−0.041, +0.019]. Deleted-premise items at depth 10 are declined 27.3% of the time against 64–91% at depths 2–8, but that cell has n = 11. The depth question needs the full 4,939-item set and several rollouts per item, as Phase A plans.

## Engineering findings that change the Phase A commands

- **vf-eval needs `--env.agent.runtime.type subprocess` to run without a Prime account.** In verifiers 0.4.0 the agent runtime defaults to a Prime sandbox (`verifiers/v1/configs/agent.py:34`, `runtime: RuntimeConfig = PrimeConfig()`). That calls `ensure_prime_auth()`, which exits with "not authenticated with prime" when `PRIME_API_KEY` is unset, even with `--no-push`. With a Prime key this default works, but the subprocess runtime is the right choice for a plain-chat harness.
- **Cap completion tokens at 16k or more for reasoning models.** A Modal smoke test at 8,192 tokens (20 items) truncated 20% of responses and left 25% without a boxed decision. At 16,384 truncation fell to 1%. A truncated response never declines, so a low cap biases the flawed-item decline rate down.
- **`records_from_traces` reads real `traces.jsonl`.** NEXT_STEPS listed its format as unverified. It produced 300 records per mode with the item fields and outcomes intact.
- **vLLM 0.31.0 on a Lambda A10 needs the `+cu129` wheel** (`--torch-backend cu129`), because the default build is CUDA 13 and needs driver 580 or later. Disable the FlashInfer sampler, which JIT-compiles with nvcc and ninja at warmup.

The A10 ran at $1.29/hr and was billed for about 126 minutes in total, about $2.71. That includes a failed first start and 22 idle minutes before termination. Earlier Modal smoke tests on an L4 cost about $0.20. Generation ran at 400–860 tokens/s with the KV cache saturated. `force` is slower because responses are longer.
